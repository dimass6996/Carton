# Carton 📦

**Carton** — учебный backend интернет-магазина на Java и Spring Boot. Проект посвящён полному циклу обработки заказа: от каталога товаров и резервирования остатков до имитации оплаты и асинхронных уведомлений.

> **Статус:** в разработке. Ниже описаны **планируемые** возможности и целевая архитектура, а не уже реализованный функционал.

## Зачем этот проект

Carton создаётся как практический проект для изучения Java Backend: REST API, Spring Boot, реляционных БД, транзакций, безопасности, тестирования и интеграции с брокером сообщений. Разработка разбита на небольшие задачи, каждая из которых посвящена отдельной концепции.

Основной принцип — **сначала работающий модульный монолит**, затем постепенное добавление инфраструктуры. Kafka и Redis не нужны для запуска первых версий.

## Возможности

### Покупатель (планируется)

- Просмотр каталога, поиск, фильтрация и пагинация товаров.
- Создание заказов с несколькими позициями.
- Резервирование товаров на складе при оформлении заказа.
- Имитация успешной и неуспешной оплаты (без реальных платежей).
- Просмотр истории и деталей **своих** заказов.
- Отмена заказа в разрешённых состояниях.

### Администратор (планируется)

- Создание, редактирование и архивирование товаров.
- Пополнение и просмотр складских остатков.
- Просмотр заказов покупателей.
- Перевод оплаченных заказов в обработку и завершённое состояние.

### Надёжность (последующие этапы)

- Транзакционное резервирование и защита от продажи сверх остатка (*overselling*).
- Идемпотентное создание заказов и обработка событий.
- Автоматическое освобождение истёкших резервов.
- Kafka-события об оплаченных заказах и обработка уведомлений.
- Transactional Outbox для надёжной публикации событий.
- Redis-кэширование карточек товаров.
- Интеграционные тесты, Docker Compose, CI и метрики.

## Бизнес-правила

- В заказе фиксируются цена и количество товара **на момент оформления**. Последующее изменение цены товара не меняет старые заказы.
- Создание заказа резервирует доступный остаток; подтверждённая оплата завершает продажу, неуспешная оплата или отмена освобождает резерв.
- Доступный остаток вычисляется как `available = on_hand - reserved` при инварианте `on_hand >= reserved >= 0`.
- Нельзя создать заказ, если товара недостаточно.
- Повторная обработка того же действия не должна создавать дубли или дважды менять остатки.
- Покупатель имеет доступ только к собственным заказам; административные операции защищены по роли.

**Основные состояния заказа:**

```text
PENDING_PAYMENT ──оплата успешна──> PAID ──> PROCESSING ──> COMPLETED
       │
       ├──отмена───────────────> CANCELLED
       └──оплата неуспешна─────> FAILED
```

Возвраты, настоящая оплата и сложная логистика не входят в первую версию.

## Архитектура

На первом этапе Carton — **одно Spring Boot-приложение** с логическими модулями:

```text
                  HTTP / REST
                      │
              ┌───────▼────────┐
              │   Carton API   │
              │   Spring Boot  │
              ├────────────────┤
              │ catalog        │
              │ inventory      │
              │ orders         │
              │ payments       │
              │ users/security │
              │ notifications  │
              └───┬─────┬──────┘
                  │     │
             PostgreSQL │
                        │ (после MVP)
                       Kafka ──> Обработчик уведомлений
                  
             Redis (кэш каталога, позже)
```

Основные сущности: `User`, `Product`, `Inventory`, `Order`, `OrderItem`, `Payment`; позднее — `OutboxEvent` и `Notification`.

**Почему не микросервисы сразу?** Основной процесс заказа должен быть понятным и транзакционно целостным. Разделение на независимые процессы имеет смысл вводить только тогда, когда появится реальная потребность в асинхронной обработке.

## Этапы разработки

- [ ] **1. Основы Spring Boot** — запуск приложения, HTTP-контроллеры, DI, DTO, валидация.
- [ ] **2. Каталог товаров** — PostgreSQL, JPA, Flyway, поиск и тесты.
- [ ] **3. Заказы и склад** — модель заказа, резервы, транзакции, отмена.
- [ ] **4. MVP** — пользователи, Spring Security, имитация оплаты, интеграционные тесты.
- [ ] **5. Надёжность** — конкурентность, идемпотентность, истечение резервов, оптимизация SQL.
- [ ] **6. Kafka** — события заказов, consumer, повторная доставка, Transactional Outbox.
- [ ] **7. Инфраструктура** — Redis, Docker Compose, GitHub Actions, логирование и метрики.
- [ ] **8. Финализация** — документация API и проверка бизнес-сценариев.

**Подробная декомпозиция: [Carton Roadmap](Carton_Roadmap.md)** — 44 задачи по 1–2 вечера с теорией, практикой, критериями готовности и зависимостями.

## Запуск проекта

Проект находится на этапе подготовки. **Команды запуска появятся после создания Spring Boot-приложения (задача C-01)**, а инструкция для PostgreSQL — после подключения БД (C-06). Необходимые сервисы и шаги будут дополняться по мере развития, чтобы инструкция соответствовала действительному состоянию репозитория.

Планируемое окружение разработки: **JDK 21, Maven, Docker и Docker Compose**.

## Подход к тестированию

В проекте планируется проверять не только успешные запросы, но и ошибки и граничные случаи:

- недостаток товара и попытка резервирования последней единицы несколькими покупателями;
- создание дублирующего заказа при повторном запросе;
- изменение цены товара после оформления заказа;
- повторное событие Kafka;
- сбой брокера во время публикации;
- попытка покупателя получить чужой заказ;
- корректное освобождение резерва при отмене или неуспешной оплате.
